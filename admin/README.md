# CivicLens Admin

Administration dashboard for **CivicLens**, a citizen issue-reporting platform.

The dashboard is connected to the CivicLens backend API: reports, status changes and
administrative notes are read from and written to the server. It uses session
authentication and only accepts accounts with the `ADMIN` role.

## Stack

- React 19 + TypeScript + Vite
- Tailwind CSS v4 (via `@tailwindcss/vite`)
- `vite-plugin-pwa` (existing manifest, icons and service-worker generation preserved)

No additional UI, routing, chart or map libraries were added: routing, charts and the
map view are implemented in the project itself.

## Scripts

| Command           | Purpose                          |
| ----------------- | -------------------------------- |
| `npm run dev`     | Start the dev server             |
| `npm run build`   | Type-check and build for release |
| `npm run lint`    | Run ESLint                       |
| `npm run preview` | Preview the production build     |

In development, Vite proxies `/api` to the backend at `http://127.0.0.1:3000`.

## Routes (hash based)

| Route               | Page                                        |
| ------------------- | ------------------------------------------- |
| `#/`                | Overview: statistics, distributions, feed   |
| `#/reports`         | Report list: search, filters, sorting       |
| `#/reports/:id`     | Report detail, status history, notes        |
| `#/map`             | Schematic map of report coordinates (`?sel=…`) |
| `#/activity`        | Administrative activity log                 |
| `#/settings`        | Administrator profile and preferences       |

When no session is present the dashboard renders a sign-in screen instead.

## Structure

```
src/
  types.ts            Domain types (reports, statuses, notes, activity…)
  router.ts           Minimal hash router (parse/navigate/useRoute)
  api/
    client.ts         Session storage, apiFetch/apiFetchBlob, ApiError
    reports.ts        Report endpoints + backend ⇄ presentation mapping
  auth/
    sessionContext.ts Session context and useSession hook
    SessionProvider.tsx Sign-in state, login/logout, 401 handling
  data/
    catalog.ts        Status and category catalog (single source of truth)
    selectors.ts      Pure statistics and filtering helpers
    store.ts          Store context / hook
    StoreProvider.tsx Store implementation (load, status/note mutations)
  lib/                Formatting, class helpers, shared control styles
  components/         ui primitives, layout shell, charts, tables, feeds
  pages/              One file per screen
```

## Data and authentication

- Reports are loaded from `GET /api/reports` (paginated; every page is fetched).
- Status changes call `PATCH /api/reports/:id/status`; notes call
  `POST /api/reports/:id/notes`. Both are administrator-only on the backend.
- The activity log is derived from the persisted status-history rows and
  administrative notes — no events are fabricated.
- Evidence photos are fetched as authenticated blobs from
  `GET /api/reports/:id/photo`.
- The session token is held in `sessionStorage` and cleared on sign-out or when the
  backend returns `401`. This is a prototype trade-off; a production build should use
  an httpOnly cookie session.

## Honest gaps

- **Priority and assignee:** not stored by the backend, so the UI shows them as not
  tracked rather than inventing values.
- **Status actor:** the `StatusHistory` model records no actor, so status changes in the
  activity log are shown without one.
- **Map:** schematic SVG canvas; markers are positioned from real report coordinates but
  the background is illustrative and not tied to real geography. A real slippy map needs
  an extra dependency and network access and is deferred.
- **PWA:** the service worker is generated by the build, but installability and offline
  behaviour have not been verified, and administrative changes are never cached for sync.
